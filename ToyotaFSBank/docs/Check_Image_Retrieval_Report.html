Check image retrieval from Fiserv

How the in-house online banking platform can fetch check images from Fiserv once Q2 is retired: the IDs involved, the API calls, the SSO alternative, and what to confirm with Fiserv. Premier core · Banking Hub ESF swagger 11.0.0 (2026.4.1).

Summary

Recommended pathBanking Hub API: transaction history gives the image IDs, DocumentService returns the image. Images show inside our own UI.
FallbackSSO to Fiserv's ITI Director viewer, as Q2 does today. Our platform replaces Q2 as the trusted sender.
Deposit itemsNeed the separate TransQuery → tranlist service. Not in the Banking Hub swagger; spec required from Fiserv.
StatusMapped from the swagger and Postman collection. Not yet tested in cert.
First test: call transaction history on a DDA account that has checks and confirm ImageInd and TrnImageId come back. Then try that ID as a DocumentId in DocumentService.

Step by step


    

  1. Get a token — POST https://bankinghub-cert.fiservapis.com/fts-apim/oauth2/v2 with grant_type=client_credentials and Basic auth. Use the access_token as Bearer on every call, plus EFXHeader with OrganizationId and a new TrnId.

    EFXHeader: {"OrganizationId":"<orgId>","TrnId":"<new GUID>"}
Authorization: Bearer <access_token>
    2. 

  2. Resolve the user's accounts from the CIF — POST {{HostName}}/partyacctrelservice/partyacctrel/partyacctrel/secured

    {
  "RecCtrlIn": { "MaxRecLimit": 50 },
  "PartyAcctRelSel": {
    "PartyKeys": { "PartyId": "3323585" },
    "ExcludeClosedAcctInd": true
  }
}
    Keep the returned AcctId / AcctType pairs — they are the accounts this user may see.
    3. 

  3. Get transaction history with image IDs — POST {{HostName}}/accttranservice/acctmgmt/acctTrn/secured

    {
  "RecCtrlIn": { "MaxRecLimit": 50 },
  "AcctTrnSel": {
    "AcctKeys": { "AcctId": "8282016372", "AcctType": "DDA" },
    "DtRange": { "StartDt": "2026-10-01", "EndDt": "2026-10-31" }
  }
}
    From each AcctTrnRec[].AcctTrnInfo read Checks.ChkNum, ImageInd, TrnImageId, TrnImageBackId. Show a "View check" icon only where ImageInd is true.
    4. 

  4. Authorize the request — when the user clicks a check, confirm the account belongs to their CIF (from step 2) before fetching anything. Image IDs must never be accepted from the browser without this check.
    5. 

  5. Download the front image — POST /document/secured/download prefix unconfirmed

    {
  "DocumentSel": {
    "DocumentKeys": { "DocumentId": "<TrnImageId>" },
    "PageRequested": [ { "PageNum": 1, "PageFormat": "PNG", "View": "Front" } ]
  }
}
    Response is the image file (application/octet-stream). View can be Front, Back or FrontBack; PageFormat can be PNG, JPG, TIFF, PDF, BMP.
    6. 

  6. Download the back image — same call with DocumentId = TrnImageBackId and View: "Back", or one call with FrontBack.
    7. 

  7. Return to the UI — stream the bytes through our backend; never expose Fiserv URLs or tokens to the browser.
    8. 



If TrnImageId is not accepted as a DocumentId

Search by keywords, then download the DocumentId the search returns. Keyword names are bank-configured — read them first with POST /document/config/secured. Operand values are not listed in the swagger; EQ is a guess.


POST /document/list/secured
{
  "DocumentListSel": {
    "KeywordSel": [
      { "Keyword": "Account Number", "KeywordValue": "8282016372", "Operand": "EQ" },
      { "Keyword": "Check Number",   "KeywordValue": "1042",       "Operand": "EQ" }
    ]
  }
}


JSON alternative to the file download

POST /document/secured takes the same body and returns DocumentRec[].DocumentInfo.PageData[] with PageNum, PageFormat, View and PageValue. PageValue is probably base64; the swagger doesn't say.

SSO explained


SSO lets a customer who is already logged into online banking open Fiserv's check viewer without logging in again. Our platform vouches for the user with a short-lived signed token; Fiserv verifies the signature with a key we registered.


SSO hand-off
Rendering…




RoleTodayAfter Q2


Identity provider — logs the user in, signs the tokenQ2Our platform


Service provider — trusts the token, shows the imageFiserv ITI Director / MSISame




    

  • Token formats: usually SAML 2.0, OIDC/JWT, or a Fiserv-specific signed post — Fiserv decides.
    • 

  • Token content: typically CIF, account and check or item reference, plus a short expiry.
    • 

  • Not the same as API auth: Banking Hub calls are server to server with OAuth client credentials. SSO moves the user's browser to Fiserv's screen.

CIF explained


CIF (Customer Information File) is the bank's master record for one customer. One customer has one CIF and can own many accounts; a joint account links two CIFs to one account. On Fiserv Premier the CIF is PartyKeys.PartyId, and it is the unique customer identifier on the platform.


CIF data model
Rendering…


    

  • Holds: identity (name, date of birth, SSN/tax ID, ID documents), contact details, customer type and flags, and links to every account.
    • 

  • Lookup: POST {{HostName}}/partyservice/parties/parties/secured with {"PartySel":{"PartyKeys":{"PartyId":"<CIF>"}}}.
    • 

  • SSN only verifies: fetch by CIF, then check TaxIdent matches. One SSN can match several parties (for example a person and their business).
    • 

  • In our platform: the username maps to a primary CIF at login; everything else — visible accounts, allowed images, the SSO token — hangs off it.
    • 

  • "External CIF": probably an ID used outside the core (Q2 or OLB customer ID) linked to the internal CIF. Confirm with Fiserv and Q2.
    • 






Build guidance



  
Authorize every imageCheck the account belongs to the user's CIF before fetching. Image IDs can be guessed.

  
Fetch on demandCall DocumentService only when a user opens a check, not when history loads.

  
Cache brieflyCache images per session for a short time; never store them long-term without a retention decision.

  
Proxy through backendStream bytes through our server. No Fiserv URLs, tokens or IDs that bypass our checks reach the browser.

  
Trace every callLog TrnId, account (masked) and outcome. Never log SSNs or image content.

  
Fail gracefullyCircuit breaker around DocumentService so image outages don't affect balances or history.
